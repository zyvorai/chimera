Fault Studio

Purpose

Operator drawer for latency, status codes, next-N API/NFC failures, stream drops, drop offset, and bandwidth caps.

When to use it

Hardening clients (Transiva) against partial transfers and API errors.

How to get there

Top bar gear, sidebar, or scenario panel → Fault Studio drawer.

What you can do

  • Arm next-N failures or one-shot NFC stream drops
  • Cap bandwidth; clear faults before clean runs

Live requests

Purpose

Stream recent infrastructure HTTP calls: method, path, status, duration.

When to use it

Debug govmomi / Transiva traffic and spot red status codes.

How to get there

Overview — Live requests panel. Top bar bell scrolls here.

What you can do

  • Toggle View All / View Less (10 vs 30 buffered rows)
  • Correlate failures with Fault Studio settings

Login

Purpose

Authenticate the browser session before any Command Center chrome or data is shown.

When to use it

Every new browser session. Mutating controls require login.

How to get there

Open http(s)://<host>:8989/__chimera/. Unauthenticated users see only the login page.

What you can do

  • Sign in with username/password (default admin / admin)
  • After login, the full overview loads

Purpose

Show live gateway-derived health: requests, error rate, sessions, bytes, exports, latency.

When to use it

First screen after login; confirm the engine is receiving infrastructure traffic.

How to get there

Command Center home — top metrics row.

What you can do

  • Refresh the window
  • Note that /__chimera polling itself is excluded from counters

Scenario Launcher

Purpose

One-click deterministic presets for clean, slow, flaky, and resume export paths.

When to use it

Repeatable Transiva / client tests without hand-tuning Fault Studio each time.

How to get there

Overview — scenario cards.

What you can do

  • Clean Environment — baseline happy path
  • Slow Fabric — latency pressure
  • Flaky API — intermittent failures
  • Resume Export — NFC drop for Range/206 retry

VM inventory

Purpose

Searchable, paginated table of simulator VMs with power state, CPU/memory/disk, datastore, and Fixture badge.

When to use it

Pick an export target; confirm fixture matching (real VMDK vs synthetic).

How to get there

Overview — VM inventory table.

What you can do

  • Filter by name and power state
  • Copy/select a VM for export workflows
  • Hover Fixture badge for filename (Matched, Round-robin, Shared, Manual, Synthetic)

VMDK Library · Workflows

VMDK Library

Purpose

List and manage .vmdk fixtures under configured fixture directories; upload or browse; optionally pin to a VM.

When to use it

Testing Transiva conversion with real disks, not only NFC transfer of synthetic fixtures.

How to get there

Overview — VMDK Library card.

What you can do

  • Upload a .vmdk into fixture_vmdk_dir
  • Browse staged host files under fixture roots only
  • Pin/clear Manual assignment (overrides name/round-robin matching)
  • Auto re-scan every ~5 seconds
